## 已锁定的决定（访谈记录）

1. **路线：光色重构 + 签名物件**。pinchen 的建筑壳保留，光换成你的语言，
   物件换成你的东西——个人辨识度从这里来，不从重建房间来。
2. **新物件**：游戏掌机角、猫、篮球 + 棒球手套里的棒球。（广州窗景、摄影墙不进。）
3. **时刻**：跟随访客本地时间，且访客可手动切换；**只动室内光，窗外不碰**。
4. **物件可深入，形态按 pinchen.me**：点击物件 → 相机推近 → 打开交互小页面。
5. **猫**：黑色狸花猫、黄色眼睛；其余（姿态、位置、动效程度）我定。
6. **掌机屏幕**：预录动图循环，不跑实时渲染。

## 个人特色的来源（本方案的立意）

「不像 pinchen」不靠换房间，靠四层替换：**光是他的时刻**（广州的夜/你的色板）、
**物件是他的生活**（猫、掌机、球、唱台）、**内容是他的声音**（终端、书、胶片里
写的是你）、**虚构是他的虚构**——全站本来说的就是「你在一台 CRT 里」，那么房间
里那台 CRT 显示器就该真的跑着 JOI9000。这是 pinchen 的终端给不了的身份感。

## pinchen 机制 → 我们的实现（核心对照）

| pinchen 的做法 | 我们的做法 |
|---|---|
| GSAP 相机飞行（power3.inOut 1.5s） | **不引 GSAP**：扩展 room3d 现有焦点相机 lerp 为逐物件机位表，同一套缓动语言 |
| DOM 覆盖层框架（背板+面板+Escape） | 新建一个通用 `RoomAppSheet`，视觉复用 menuSheet 语言（rgba(5,7,11,.82)+blur、mono、珊瑚色），带焦点管理 |
| 终端 = CanvasTexture 贴 MacBook 屏 | 同方案贴到**房间里的 CRT 显示器**（绿磷光配色，呼应全站虚构）；桌面 window keydown，移动端隐藏 input 桥（pinchen 已验证的手法） |
| 书 = 数据生成的 3D 网格 | **我们的 GLB 里 book1–10 本来就是真实节点**——书架时间线直接驱动现有 mesh：选中哪本，哪本从架上滑出一点 |
| 胶片册 = 胶卷数据 + DOM 排印（齿孔/框号/edge text 全是画的） | 同方案，内容换成你的胶卷；相机节点（film/film001）在 GLB 里已存在 |
| 四套光照烘焙切换 | 我们只有 light-day：**调色派生**——烘焙图 × 分档 tint + 2–3 盏实用点光（台灯暖光/屏幕冷光），不抓他的 night 烘焙（依赖越挖越深） |
| IndexedDB 存涂鸦 | 若做涂鸦面则照抄此模式（库 `room-local-state`，localStorage 回退） |

## Phase A · 地基：交互框架 + 时刻系统

- [ ] **逐物件机位表**：room3d 焦点相机从「统一拉近」升级为每物件一组
      `{position, lookAt}`（以 roomBase.ts 实际节点名为准核对 GLB）；
      reduced-motion 时跳过飞行直接切机位。
- [ ] **通用 `RoomAppSheet` 覆盖层**：背板 + 面板 + Escape + 焦点陷阱 +
      关闭还焦点；桌面半幅 / 移动端全幅两档（pinchen 的 1024 分界同款）。
- [ ] **时刻系统**：三档（DAY / BLUE / NIGHT）＝烘焙图 tint 分档 + 实用点光
      （台灯/屏幕辉光）；按本地时间取默认（约 7–17 昼、17–19:30 蓝调、其余夜），
      房间角落一组 mono 小切换钮（DAY/BLUE/NIGHT），选择记 sessionStorage。
- [ ] **色板校准**：三档 tint 都向你的四色板（`#0a1221 / #f2eee8 / #ed654a /
      #294f82`）靠——夜档深蓝环境 + 暖钨丝室内是签名画面。

## Phase B · 物件进房

- [ ] **猫**：按「黑狸花/黄眼」建分部件模型（img2threejs 管线或程序化，风格向
      房间材质收敛）；待机 = 呼吸（scale 微起伏）+ 偶发耳朵/尾巴抽动；
      点击 = 抬头 0.8s + 尾巴摆一下；reduced-motion 全静态。
- [ ] **掌机角**：复用 night-tide 掌机模型缩小进房，落在桌面/床头；屏幕 =
      预烘焙 flipbook 图集循环（几帧像素游戏画面，类 reel 手法，无视频解码成本）；
      点击 → 卡带菜单 sheet（四盘卡带 → /play/night-tide 对应游戏）。
- [ ] **篮球 + 棒球手套**：桌面下/墙角落位；hover 高亮 + 标签；点击篮球轻弹
      两次滚动回位、棒球在手套里轻晃（解析运动，无物理引擎）。
- [ ] **性能与生命周期**：新物件只进 About 小上下文；几何/材质/纹理进
      ownedTextures 清单随场景释放；flipbook 图集 <300KB。

## Phase C · 深入交互（pinchen 形态，你的内容）

- [ ] **CRT 终端**：CanvasTexture 管线（DPR 感知、无 mipmap、anisotropy 上限）；
      命令解析器（help/about/works/lab/games/socials/contact/echo/history/clear +
      Tab 补全 + 箭头历史）；移动端隐藏 input 桥（pinchen 同款 1px input 手法）。
- [ ] **阅读时间线**：`roomBooks.ts` 数据模块（书名/作者/年份/note/quote/封面色）；
      覆盖层 = 年份刻度轴 + 选中书详情；联动：选中 → GLB 里对应 book 节点滑出。
- [ ] **胶卷册**：`roomFilms.ts`（胶卷名/年份/张数/照片路径/edge text）；
      覆盖层 = 胶卷 Tab + 横向照片条 + Kodak 式排印；照片懒加载。
- [ ] **卡带菜单 sheet**（掌机）：静态菜单 + 路由跳转。

## Phase D · 文案与打磨

- [ ] **标签写成人话**：八个物件的标签从词条变成一句话故事（第一人称、双语），
      我起草 → 你改定稿（COPY-REVIEW 流程）。
- [ ] **移动端**：sheet 全幅；终端降级为只读欢迎演示（免键盘桥复杂度）——
      见开放位 §A.6。
- [ ] **无障碍**：chips 是真实按钮可达（键盘走焦点顺序），sheet 焦点陷阱，
      物件 hover 标签同步 aria。
- [ ] **核查**：`npx tsc --noEmit`；逐机位深链检查；dispose 清单核对；
      读 computed style 验证 tint 切换（不靠截屏）。

## 明确不做

- 不重建房间几何（pinchen 壳保留到 Phase A–D 全程）。
- 不抓 pinchen 的 night/off 烘焙图集（tint 派生，把光照依赖锁在已采集的一套）。
- 不把 YouTube 流音乐搬进来（我们已有全站 GlobalMusic 体系）。
- 不复制 pinchen 的任何内容数据（项目/书/胶卷/命令输出全是你的）。
- 猫不做走动寻路、球不做刚体引擎（成本收益不成立）。
