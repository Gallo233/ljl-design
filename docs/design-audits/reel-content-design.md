## 二、六格内容设计

### 技术前提（先说，因为它决定内容怎么做）

现在的图集是 `4096 × 512`，六格平分 → **每格约 683 × 512**。这个分辨率放静态示意图勉强够，放真机演示会糊。

参考 shader.se 的做法：
- 静帧走 Mux，每张 **800 × 600**
- 动态画面走**预烘焙 AVIF 精灵表** + manifest，不用 `<video>`

建议：
- 图集升到 `6144 × 768`（每格 1024 × 768），或者干脆**每格一张独立贴图**（更好，可以按需加载）
- 两格真机演示走精灵表：录屏 → 抽帧 → 拼成 2~3 张 AVIF sheet + manifest。这样帧可以跟着拖拽精确擦洗，还绕开自动播放策略

### 01 · JOI / PRESENCE

**胶片画面**：Windows 桌面真机录屏。Joi 悬浮窗贴在屏幕右侧，正在读一封邮件；下方 agent trace 四步（OBSERVE → PLAN → APPROVE → REPORT）依次点亮。整段循环 4~6 秒，**关键是要有"她在等你点同意"那一帧**——这是 Joi 的产品主张。

**点进去**：`/joi` 现有详情页。Live2D 在这里挂载并接管——从胶片进来的人，落地时正好看到她动起来。这条动线本身就是叙事：**在机器外面看她的录像 → 走进去她本人在**。

**素材**：Windows 录屏（1024×768 裁切）、抽帧 → AVIF sheet。

### 04 · 实验室 / LAB

**胶片画面**：**印相纸接触表**（contact sheet）——一格里排 6~9 张小样，边上有蜡笔圈出的"选用"标记。这个形式天生适合装"很多小东西"，而且完全长在胶片的隐喻里。小样可以缓慢轮替。

**里面装什么**：

**关于司天监**：概念是你整个作品集里叙事上最有意思的一个——司天监年轻推官得"飞符"，可向数时辰前的自己写信，每次改写都搅动天命之衡；中日双语，目标 itch.io / Steam / DLsite。但它现在是 **M0（环境搭建中）**，实际没有可截的画面。

**点进去**：实验列表页。每条给"在试什么 / 试到哪 / 学到什么"三段，不需要完整 case study。

## 三、主站融合方向

### 核心矛盾

主站是**浅色瑞士编辑风**，joi-signal-lab 是**深色 CRT**。这不是调色能调和的差距，得做取舍。

### 我的建议：让两者分工，而不是二选一

```
CRT 机器内部  =  首页外壳（hero + 胶片轮播）
浅色编辑风    =  详情页（走出机器，进入文档）
```

理由：

1. **对比本身就是叙事**。你在一台老机器里翻看作品的缩影，点进去是干净的白纸案例研究——"从机器里走出来"。这个转场值得设计，而不是要消除。
2. **两边的投入都保住了**。你已经建好的 case-study schema、双语内容、`[slug]` 路由全部继续用，一行不浪费。
3. **入场仪式的冲突自动解决**：CRT 开机屏接管入口（同时正好当预加载器，参考 shader.se 那 5.2MB 的做法），Live2D 从门口移到 `/joi` 详情页——**这正是你自己想要的那条动线**。

### 需要你拍板的

1. **首页的 01/THOUGHT 宣言放哪？** 我倾向做成 CRT 开机自检的滚动文字——开机时逐行打出来，比单独一屏更合题。
2. **主站现有的浅色 hero（"I DESIGN HOW AI ENTERS HUMAN LIFE"）留不留？** 如果 CRT 当首页，这句话可以移到开机屏之后的第一帧，或者移进 ABOUT。
3. **域名/路由**：`/joi-signal-lab` 变成 `/`，现在的 `/` 退役还是保留成 `/classic`？

### 落地顺序（建议）

| | 阶段 | 说明 |
|---|---|---|
| 1 | 内容先行 | 六格的**素材**先备齐（录屏、3D 桌面、角色设定稿）。没有真素材，渲染做得再好也是空壳 |
| 2 | 图集升级 | 683×512 → 每格独立贴图 1024×768，两格演示走 AVIF 精灵表 |
| 3 | 数据打通 | `projectData.ts` 从 2 条扩到 6 条，胶片格直接读它，别再维护两份 |
| 4 | 视觉统一 | 再回头做后期链 / bloom 那些（上一轮的工作还留在 scratchpad） |
| 5 | 路由切换 | 首页换成 CRT 壳 |

**顺序很重要**：先内容，后渲染。上一轮我们直接冲渲染，结果是给六个占位图加特效——本末倒置了。
