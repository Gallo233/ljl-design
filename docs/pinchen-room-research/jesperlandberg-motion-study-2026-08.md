# Jesper Landberg 动效与滚动系统研究

> 研究对象：<https://jesperlandberg.com/>  
> 抓取日期：2026-08-29  
> 研究范围：主页、项目详情、`/full/` 项目索引、跨路由转场、输入与资源调度  
> 证据目录：[`.web-shader-extractor/`](./.web-shader-extractor/)

## 先说结论

这个网站最值得借鉴的不是某个 shader，而是它把**滚动、形变、转场和资源状态收束到同一条运动信号**：输入先进入一个虚拟位移目标，显示位置再追随目标；两者的差值既制造惯性，也驱动卡片形变和运动反馈。页面切换时，同一张项目卡片不消失，而是由持续存在的 WebGL 平面飞到详情页的新矩形中。

它的视觉体系很激进：DOM 负责真实排版、语义和点击区域，但 DOM 文字与图片本身透明，所有可见像素由一个固定的 Three.js 画布绘制。这个架构让所有元素共享同一种空间感，却也带来可访问性、失败回退、调试和性能风险。对 Gallo 个人站，适合借用它的**输入归一化、速度信号、节奏阶梯和局部共享元素**，不适合照搬“全站像素 WebGL 化”与“全站虚拟滚动”。

## 1. 运行模型

### 1.1 页面不是在原生滚动

桌面主页是固定视口：`document.scrollY = 0`，项目卡片在横向无限轨道中移动。滚轮、触摸板、拖拽和键盘都被转换为同一套位移量：

```text
输入 delta
  → target（意图位置）
  → current（显示位置，逐帧追随）
  → lag = target - current
  → velocity = sign(tanh(lag / 550)) × tanh(lag / 550)²
  → 卡片位移 + 纵深/弯折反馈
```

核心追随式：

```js
current += (target - current) * (0.1 * min(frameRatio, 2));
current = round(current, 0.01);
```

这里的 `frameRatio = frameDuration / (1000 / 60)`，所以不同刷新率下的手感大致一致。`0.1` 不是单纯的“慢”，而是留出稳定的 `lag`，让画面能够感知用户正在加速、滑行还是收手。

### 1.2 无限循环不是复制整个页面

每张卡片保留自己的原始矩形，再按轨道总宽做模运算。越过一端的卡片被包装到另一端；离视口较远的卡片进入 parked 状态，减少不必要的更新。桌面主页使用横向循环，项目详情与小屏版本使用同一思想的纵向列。

详情页为了避免循环露馅，会重复图片直到内容栈至少达到约 `1.15 × viewportHeight`。在细指针桌面上可无限循环；触屏上改为有限、可夹紧的滚动。这是很成熟的设备差异：鼠标用户得到玩具感，触屏用户得到可预期的边界。

### 1.3 一个 DOM，两种职责

DOM 元素仍然真实存在，负责：

- 内容、排版与响应式尺寸；
- `getBoundingClientRect()` 提供 WebGL 平面的目标矩形；
- 链接、按钮、hover 和点击命中；
- 跨路由共享元素的 `data-id` 身份。

但页面将 DOM 可见内容设为透明，再把文字逐字符测量、绘到 `CanvasTexture`，图片转为纹理，交给 Three.js 显示。因此圆角、位置和尺寸仍由 CSS 决定，而弯折、深度、拖尾和转场统一发生在 WebGL 中。

这也解释了自动化浏览器中的截图为什么是黑的：DOM 结构可读、WebGL 正常运行，但当前抓取环境拿不到 GPU 合成后的像素。源码、运行时 DOM、资源请求和交互状态仍形成了完整证据链；视觉逐帧比对被明确列为缺口，而不是假装通过。

## 2. 输入与滚动逻辑

### 2.1 滚轮与触摸板被区别对待

源码中的输入常数：

| 输入 | 处理 |
|---|---|
| 像素滚轮 | `delta × 1.25` |
| 行模式滚轮 | 先 `× 16`，再进入统一尺度 |
| 页模式滚轮 | 先 `× viewportHeight` |
| 独立的大滚轮刻度 | `abs(delta) ≥ 40`、事件间隔 `≥ 30ms`、且 500ms 内无 burst 时，再乘 `2` 进入惯性池 |
| 触摸移动 | `delta × 3.25` |
| 触摸松手 | 最后速度脉冲 `× 35` |
| 鼠标拖拽 | 水平移动 `× 1.5` |
| 拖拽松手 | 100ms 内的最后增量 `× 12` |
| 方向键 | 每次 `100px` |
| Page / Space | 每次 `0.9 × viewportHeight` |

离散鼠标滚轮不直接生硬跳动，而是进入惯性池。每帧取出：

```js
step = inertia * (1 - (1 - 0.22) ** min(frameRatio, 4));
```

绝对值小于 `0.05` 时清空余量。触摸板连续事件则直接进入待处理增量，保持贴手。也就是说，它不是给所有设备套同一个 damping，而是先判断输入语义。

### 2.2 拖拽有意图判断

拖拽只有在水平位移超过 `10px` 且横向大于纵向时才成立；一旦成为拖拽，松手后的点击会被抑制。这个细节避免用户想打开项目时因为一两像素抖动而误触，也避免垂直手势被横向画廊抢走。

项目详情的左右换页使用另一套门槛：水平位移先按 `0.8 × viewportWidth` 归一化，再经压缩函数形成可视 scrub；原始归一化位移超过 `0.25` 才提交换页，否则以 `0.6s expo.out` 回弹。视觉预览可以柔软，业务决定保持明确。

## 3. 动效节奏

### 3.1 不是所有东西同时开始

页面把动效分成主动作、结构动作、内容动作和控件动作：

| 层级 | 开始 | 时长 | 典型缓动 |
|---|---:|---:|---|
| 共享平面飞行 | `0s` | `1.0s` | 自定义三段 cubic |
| 卡片/结构堆栈 | `0.25s` | `1.25s` | expo |
| 大标题 | `0.25s` | `1.25s` | expo，步进 `0.075s` |
| 正文 | `0.35s` | `1.1s` | 步进 `0.075s` / 行步进 `0.09s` |
| pills / 次级控件 | `0.5s` | `0.85s` | expo |

这个节奏的关键不是具体数字，而是**主物体先给方向，结构随后稳定，内容最后变得可读**。用户在前 250ms 已理解去向，然后才接收标题和正文。它避免了“所有元素一起淡入”的模板感。

首页卡片揭示使用约 `0.7s power1.out` 的初次推入，再以 `1.25s expo.out` 落稳。首次启动的卡片飞行是 `1.5s`，逐张错开 `0.05s`；滚动锁在画面完全静止前就释放，让交互与尾部动效有一小段重叠，因此显得活而不是像开场视频。

### 3.2 自定义飞行曲线

共享元素飞行使用三段 cubic 组合，而不是单一标准 ease：

```text
[0,0 → .157,.29]
[.157,.29 → .348,.884]
[.348,.884 → 1,1]
```

体感上是：快速建立方向，中段完成大部分位移，尾段用较长距离安定。它同时插值位置、旋转、缩放、透明、阴影、圆角和 sheet progress，因此不会出现“盒子已经到位，但材质还在追”的脱节。

### 3.3 单时钟比更多动画更重要

GSAP 被关闭 `autoSleep`，lag smoothing 设为 0；渲染循环自身把大帧间隔夹到 50ms。页面的滚动追随、shader 时间、hover、路由转场与资源揭示共享一个领导时钟。真正形成高级感的是这些系统彼此知道对方所处的时间，而不只是分别用了漂亮的 ease。

## 4. 跨路由转场

项目卡片和详情页首图共享同一个 `data-id`。路由切换时，站点级 renderer 不卸载；平面注册表先保存旧矩形，再接管新页面的同名矩形，执行约 1 秒飞行。标题也单独在旧、新测量矩形之间飞行。其余内容按前述节奏阶梯进入。

这是真正的 shared element，而不是两张图交叉淡化。核心前提有三个：

1. renderer 生命周期高于路由；
2. 两个页面对同一项目使用稳定身份；
3. 新页面 DOM 先完成测量，视觉层再迁移。

站点还设置约 400ms 的路由 hop 间隔，合并连续导航请求，避免用户快速连点时多个飞行互相覆盖。

## 5. 指针、后处理与微反馈

指针位置使用 `1 - exp(-7dt)` 平滑。指针速度经过阈值与平方整形后进入 256px 宽的 ping-pong trail 纹理；反馈场的衰减率约 `4`、扩散约 `40`。最终后处理使用小幅球形扭曲（约 `-0.045`）和边缘遮罩。由于输入、拖尾、图片平面和文字都在同一 renderer 中，指针像是在推动同一块介质。

Profile / Newsletter 等覆盖层不是另开普通 modal：DOM 仍负责内容与命中，WebGL 则开一个以 DOM 矩形为中心的“洞”。打开约 `0.85s`，关闭约 `0.65s`，并附带 squash、镜头、色差与呼吸参数。这个设计很完整，但其视觉性格强，不适合直接移植到 Gallo 的 CRT → editorial 对比中。

## 6. 资源与性能策略

- 图片优先请求 KTX2；公共 manifest 记录压缩资源，失败后回退原图。
- Basis transcoder 独立加载；纹理各向异性上限为 `min(8, deviceMax)`。
- 初屏并发预加载约 6，缩略图约 2，项目媒体约 4。
- Mux 视频为 muted / loop / playsInline；页面隐藏或项目离屏、parked 时暂停。
- `saveData` 或 2G 网络不做预取。
- renderer DPR 上限为 2；地面反射只用 drawing buffer 的约 10%；拖尾纹理固定较低分辨率。
- 首帧有最长 3 秒保险；资源加载进度以 `0.8s power3.out` 平滑。若加载不足 1 秒，会补约 0.5 秒停留，避免 loading 一闪而过。

未在已检查源码中发现 `prefers-reduced-motion` 分支。这不是建议照搬的部分。

## 7. 给 Gallo 个人站的迁移建议

### P1：低风险、最值得做

1. **为 film reel 增加统一输入归一器，但限制作用域。** 让滚轮、触摸板、水平拖拽和键盘最终都驱动 reel 的同一目标值；页面整体仍保留原生纵向滚动。这样不会破坏现有四段地址、深链、阅读区与 snap 约束。
2. **把 `target - current` 变成 reel 的形变信号。** 先测试：

   ```js
   const x = Math.tanh(lag / 550);
   const velocity = x * Math.abs(x);
   ```

   用它轻微驱动胶片的弯折、纵深或光晕，不再从原始 wheel delta 直接取噪声。阈值要按本项目的滚动单位重新标定，`550` 只作为桌面起点。
3. **借用节奏阶梯。** 项目打开时：主画面 `0–1.0s`，标题/结构从 `0.25s` 开始，正文从 `0.35s` 开始，次级控件从 `0.5s` 开始。现有 `ArrivalFade` 的 reduced-motion 逻辑保留。

### P2：原型验证后再合入

4. **只为 reel → case study 做局部共享元素。** 当前 stage 属于 CRT 世界，详情页属于浅色 editorial 世界，没必要把 renderer 提升为全站永久层。可先记录点击帧的屏幕矩形，在 cream veil 下面维持一张“held plane”或 View Transition，等详情首图就位后交接。用 feature flag 验证 WebGL 失败、后退和 reduced-motion。
5. **让 boot 的锁释放早于尾动画结束。** 保留最长等待保险和内容可见回退；只借用“先明确状态、再让尾动画与可操作时间重叠”的节奏，不增加新的黑屏门槛。

### P3：仅在测量证明需要时

6. **KTX2 manifest。** 当 reel 静态图真正变成高分辨率摄影、纹理下载成为瓶颈时再引入。当前视频纹理和实时 render target 不是它的主要受益者。
7. **跨路由永久 renderer。** 这是结构重写，不应为了一个转场先支付。只有多个详情页都需要持续 WebGL、且 profile 显示 context 重建显著影响体验时才考虑。

### 明确不要照搬

- 不把全部 DOM 内容设为透明并依赖 WebGL 重绘。现有项目的原则是“机械层失败也不能带走内容”，应继续成立。
- 不用全站虚拟滚动替换 `useScrollDriver` 的原生页面滚动。它会与 `/selected-work`、`/about-me`、`/contact` 深链、地址同步和长文阅读冲突。
- 不把 pointer trail / hole modal 强塞进 CRT 与浅色案例页；除非放在 `/lab` 作为独立实验。
- 不采用原站缺失的 reduced-motion 策略；本项目必须提供静止/短时版本。

## 8. 推荐实施顺序与验收指标

| 阶段 | 改动 | 验收 |
|---|---|---|
| A | reel 局部输入归一与速度整形 | 触摸板贴手；离散滚轮不跳；键盘可用；About/Contact 原生阅读不受影响 |
| B | 速度驱动胶片形变 | 低速几乎无形变，高速有方向感，停手后 300–600ms 内安定，不晕动 |
| C | route timing ladder | 点击后 100ms 内确认响应；1s 内主画面完成；正文不早于主方向 |
| D | held-plane 共享元素实验 | 前进、后退、刷新、深链、WebGL 失败、reduced-motion 六条路径均不空白 |
| E | 资源压缩（按需） | 以真实 LCP、GPU memory、纹理下载量证明收益后才保留 |

建议先在 FilmCanvas 内做 A/B，不修改 `sections.ts` 的段落边界，也不改变 `REEL_ANCHOR`。共享元素实验应围绕现有 300ms cream handoff 设计，不能让详情内容依赖 WebGL 平面才可见。
